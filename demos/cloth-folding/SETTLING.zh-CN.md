# 被动沉降观测

[English](SETTLING.md) | [简体中文](SETTLING.zh-CN.md)

**已实现并通过人工状态序列测试；新的远端动力学运行和完整发布门禁待完成。** 尚无实测首次穿透时间，也未宣称物理问题已修复。

历史轨迹在两秒被动沉降、机械臂规划及速度/时间归零之后才开始记录，首帧就与桌体相交，无法知道相交何时首次出现。新增可选记录器覆盖规划和归零之前的初始化阶段。

## 在已通过资格验证的仿真主机上记录

通过正常资源准入后，使用现有机器人资产配置和新的输出目录：

```bash
bash demos/cloth-folding/run.sh --task grasp --timestep .00025 \
  --record-settling --no-video --output demos/cloth-folding/runs/settling-diagnostic-v1
```

该命令仍运行完整抓取。初始化保持 2 秒、CG、100 次迭代和 0.5 ms 步长，操作阶段仍切换为 Newton 和指定步长。参数来自现有演示，并非材料实测标定。记录默认关闭；开启时复制初态及全部 4,000 个沉降物理步，完成时共 4,001 个状态。

`settling/` 保存初始化编译模型、时间、实际 `qpos`/`qvel`、三角形拓扑、源码/文件哈希、引擎身份和完成状态，不保存接触距离或力。复制不执行动力学、接触查询，也不修改正在积分的数据。记录增加开销，不能作为原基线测速；派发前须计入新增数组和模型预算，实际远端输出大小尚未测量。

发生 Python 异常时，保留成功记录的前缀，另存 `failed-state.npz`，标记未完成并继续抛出异常。拒绝已有输出目录。进程终止或磁盘写入失败仍可能留下不完整目录：这不是防崩溃日志或完整重启检查点。

## 不积分的离线检查

归档后，在原始记录之外写入新报告：

```bash
.venv/bin/python demos/cloth-folding/src/settling_trace.py \
  demos/cloth-folding/runs/settling-diagnostic-v1/settling \
  --output demos/cloth-folding/runs/settling-onset-v1.json
```

分析器核对哈希、物理步时间网格、实际状态维度和拓扑。通过运动学重建布料，用已通过独立算例测试的三角形内部—盒体算法逐保存步检查，直到首次检出侵入。报告见证三角形、坐标/深度、前一个未检出侵入的采样时刻和实际检查帧数。初态已相交时，没有前一个清晰样本。未完成的记录前缀即使未检出相交，也仍标为未完成。

10 nm 数值零容差是几何计算容差，不是新增物理验收标准。检查零厚度布料中面与已验证的实心桌体，不覆盖布厚、机器人接触、支撑力或抓取成功。检出首个侵入后不再几何检查后续帧。相邻物理步不能保证步间持续分离，前一个清晰样本也不是首次连续时间相交的下界。退出码 0 只表示分析完成，不表示物理通过。

## 验证与下一次实验

人工状态测试覆盖顶点均在桌外而内部穿插、初态相交、无相交序列、缺步、文件损坏、异常前缀、拒绝覆盖和只读分析。使用替代步进函数核对开启/关闭记录均调用相同的 4,000 次初始化步骤且最终状态相同；这不等于原生动力学回归。

下一步在远端运行原配置，保留初始化和完整抓取记录，定位首次采样侵入，再设计接触/网格单变量对照。[桌边接触](TABLE-CONTACT.zh-CN.md)与[布—机器人](ROBOT-CONTACT.zh-CN.md)诊断继续作为独立证据。官方引擎二进制、控制命令和物理阈值保持不变。
