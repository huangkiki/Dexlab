## 给它一段擦杆视频，会得到什么？

一只手拿海绵，另一只手拿杆。给 Agent 看手机视频，它要搭出能夹、能擦、能观察接触的场景。海绵表面画得像还不够，夹住后会不会变形、擦时会不会在手里动、支撑会不会被推走，都要分别用执行结果检查。RoboSimStudio 把这些行为放进同一个反馈循环。人可以试操作，Agent 可以从检查结果回到场景代码改设置，再跑一遍。 [论文 §1、§3](https://arxiv.org/html/2610.18835v2#S3)

*图 2。物体描述、物理选择与操作接口分开。场景交互负责暴露行为，现实一致性要靠观测和对照来验证。*

### 同一个场景，四个部分

1. **场景和动作。** 资产定义物体和机器人，场景选择求解器、碰撞与耦合。机器人接口覆盖 Panda、UR5e、单和双臂 YAM，有关节、末端运动和守护式接触等操作。仿真真值与部署能看到的观测分开。
2. **求解器和反馈。** Newton 组织物理，默认关节路径可用 MuJoCo-Warp，线缆与布可用 VBD，软体可用外部 SuperDex。根据路径，互换接触力或姿态和力／力矩。反力有没有回到手上、何时生效，都取决于具体耦合配置。冻结擦拭记录使用 60 Hz 控制，每周期 16 个刚体子步和 2 个 SuperDex 步。这个时间配置只属于该队列，不能推广到全部场景。
3. **人可以操作，也可以改参。** Viser 场景能选取、拖动和检查物体。固定实现的材料参数有三种应用路径。布料本构数组可在下一子步生效，按值捕获的接触标量需要重新捕获 CUDA 图，几何与密度等构建时参数需要重建。部分接触标量作用于全局，两个布片也许共享一个值。
4. **Agent 接收动作对应的结构化结果。** 反馈包括目标误差、物体运动、接触、抓住或滑脱、任务进度，也能取得视图/运行日志。比如发现没擦到杆，先查指令和接触，再决定调整路径还是补几何。人可以在同一个场景修正模型或反馈。

## 回看失败，先分清哪一层坏了

![原论文图 7h，真实擦拭推动了支撑](https://arxiv.org/html/2610.18835v2/figures/wipe_failure.jpg)

*图 7h。原文硬件擦拭失败的一帧，支撑移动在修订前的仿真中被固定约束排除。* [论文图 7](https://arxiv.org/html/2610.18835v2#S4.F7)

**论文硬件失败在支撑边界。** 真实杆支撑是可动的，原始仿真却把它固定在环境。擦拭加载后真机支撑移动，海绵失去接触，擦拭中断。像擦一块松置的板和擦一块固定的板，横向阻力会把前者推走。这个类比只解释自由度，无法给出移位门槛。作者释放支撑为自由刚体后，仿真在较大载荷或偏心动作下出现位移、倾覆。要进一步区分摩擦滑动与倾覆，还需要同一擦拭动作下的支撑位姿、受力位置和载荷时序。修订仿真只说明它现在能出现这个现象。 [论文 §4.3](https://arxiv.org/html/2610.18835v2#S4.SS3)

**DexLab 公开 demo 的配对失败在保持层。** 固定编译碰撞几何和抓取就绪检查。原版在就绪后对一组海绵材料点施加柔顺位置约束，跟随实测手运动，松手时移除。负对照的约束数始终为零。两组约 **14.35 s** 开始擦拭。无辅助组在擦拭段的材料区域相对手位移达到 **237–242 mm**，约 **28.48 s** 检测到压靠失败后退出，清洁率 **39.92–41.15%**，**0/3** 达标。原版持握期区域质心位移约 **0.061 mm**，清洁率 **95.47–95.89%**，**3/3** 达标。可把辅助约束想成把接触区用软弹簧牵住，海绵仍会变形。这组对照识别了辅助在这个配置里的作用。下一判因需要同步首处材料相对运动、两侧法向与切向力、实际运动和跨求解器反力，才能拆开保持损失成因。 [DexLab 既有实测、视频与原始记录](rss-wiping.md)

## DexLab 已经有哪一块，值得补在哪里？

现有擦拭入口能看回放、独立复算曲线与评分，已有读回证据可以直接复用。值得带到操作入口的是**显示一次修改何时生效**：当前参数、请求值、需要刷新还是重建、触发了哪份运行记录。若以后讨论是否要做更完整的实时试参 UI，用一个已有法向加载—卸载案例验证从改一个参数、确认生效到对齐力曲线能否在同一入口走通。只要现有入口已经能给出可核对的参数生效证据，就复用它。当前公开 #247 已保留擦拭跨批次差异和耦合归因的追踪，本文沿用该工作项。 [DexLab 选型与法向案例](selection.md) · [原 Discussion #220](https://github.com/huangkiki/Dexlab/discussions/220) · [未决证据 #247](https://github.com/huangkiki/Dexlab/issues/247)
