# 切割表面重建：实现了什么，仍与 BladeMaster 差什么

这一页只评价表面拓扑和运动绑定。它不把可见切缝当作材料已经正确分离的证据；机械连通、接触与动量仍由原生粒子状态和独立评分器验收。

## 已按论文 III-F 实现的部分

豆腐和香蕉现在共用一套参考构型表面重建：

1. 在均匀参考网格的主边上保存原始边界和记录刀面的 Hermite 交点与单位法向；
2. 只有当同一刀的原生粒子历史在局部同时出现侧别 1 和 2 时，才断开候选主边；未标记的底部继续连接；
3. 仍连通时，在每个单元内对剩余连接求局部连通分量，并为每个分量解一个 QEF 对偶顶点；保存状态出现独立机械分量后，分别用记录切面的半空间为各分量重建闭合局部体，禁止同一三角形共享不相容运动场；
4. 完整切割为相邻分量生成位置重合、法向相反的切面；
5. 每个表面代表点继承原生机械分量和持久切割编码，再以固定三线性权重跟随相容的 TLMPM 运动场。

解析验收覆盖原始 Hermite 点落在零水平集、法向单位长度、无切割闭合表面、完整切割后的两块、正交相交切割后的四块、部分切割的下部连接、相反切面法向、无开边和无退化三角形。回放不增加切口位移；当前公开的平行完整切割也不在一个三角形内混合不同原生机械分量。

## 表面稳定性与 RTX 展示

切推页采用修复后的显示表面和 OVRTX 路径追踪。旧 QEF 求解保留了香蕉曲面上约束很弱的切向方向，不稳定代表点随后被裁到单元边缘，形成毛刺。修复将低于最大奇异值 10% 的方向作为零空间，在这些方向保留 Hermite 样本质心；凹对偶四边形则选择投影三角形面积更合理的对角线。精确切面和原生机械分量仍是约束。这修改的是重建显示网格，没有改变保存的粒子或力学结果。

局部切割标记不能裁掉仍相连物块另一侧的未标记材料。香蕉第三刀在 4.70 s 刚开始时，只标记了单侧 5 个粒子；旧显示错误地让右段消失一帧。修正判断后，已用原生样本 470 重渲染第 94 帧，并检查相邻状态；扫描全部 161 帧香蕉和 121 帧豆腐后，没有其他受影响帧。记录保留初版渲染哈希和逐帧修复来源，没有复制邻帧或插帧。

初始香蕉中，相对解析法向朝内的三角形由 540 个减少至 8 个；剩余标记位于人工形状不可微的端盖，光滑侧面为零。参考边界最大残差从 1.233 mm 降至 0.454 mm。在 0、0.8、8 s 的选定检查帧中，新旧显示顶点的世界坐标最大差为 1.834 mm。这些是**显示重建诊断**，不是材料精度估计。[选定帧记录](https://github.com/huangkiki/Dexlab/blob/main/demos/cut-push/surface-quality.json)保留前后两版数据。

柔和面光源、PBR 粗糙度、材料坐标中的纤维和切面纹理只描述外观。没有顶点平滑、时间插帧或新的物理步。只有全部原生切割编码和分量标签不变时才复用已分离物块的参考拓扑，每帧仍重新计算保存的 `x/F` 运动场。渲染后逐帧读回 OVRTX 网格点及物体、相机变换。完整 20 fps 回放覆盖香蕉 161 帧、豆腐 121 帧；GIF 保持每帧 120 ms 的统一慢放。

## 仍未与原文完全一致

| 原文能力 | 当前边界 |
| --- | --- |
| 有限刀刃逐子步扫掠并在线断开实际相交的参考边 | 回放从保存刀轨恢复 x/y 轴直切平面，再结合持久侧标记判断局部断边；横向扫掠超过半个材料采样间距会拒绝，尚不支持任意弯曲或倾斜刀路。 |
| 只更新本步受影响单元 | CPU 回放重建发生变化的参考拓扑，并复用未变的已分离物块拓扑；没有实现作者的 GPU 局部更新路径。 |
| 表面点直接嵌入当时的相容 TLMPM 运动场 | 历史记录没有保存逻辑网格运动场；当前每个所需节点都由同一机械分量内相容粒子的已保存 `x/F` 仿射预测做局部高斯平均，共同仿射场仍能精确重现。保存状态已经分离时，当前实现还会按原生机械分量分别重建闭合局部体，而非完全照搬论文逐单元在线更新。拓扑来自原生历史，但粗粒子形变仍可能留下细小外表面伪影。 |
| 作者使用的表面网格分辨率与几何资产 | 未公开。DexLab 独立采用机械网格间距四分之一的表面网格；香蕉仍是人工曲面，不是作者或真实样品扫描。 |
| 完全切穿的相交切面随后独立运动 | 解析测试覆盖四个独立闭合区域，但尚无正式记录和公开视频验收交线附近的独立运动；当前交叉任务只验收底部仍连接的浅切。 |
| 已分离物块内部继续形成下一条浅切裂纹 | 完整切割形成的新分量会保持闭合并在下一刀完成后再次分裂；但“前一刀已分离、后一刀尚未切穿”这一中间裂纹尚未单独验收，不能据最终帧推断其逐帧表面拓扑完全等同原文。 |
| GPU 紧凑活动状态与实时性能 | 未实现；表面由 NumPy/SciPy 在 CPU 离线重建，再采用 VTK 或 OVRTX 展示，不能复现论文实时性能。 |

因此可以说“当前直切任务采用了论文式 linked volume、Hermite 数据和局部 dual contouring”，不能说“完整复现了 BladeMaster 表面系统”。公开媒体的 `provenance.json` 保存记录哈希、渲染源码哈希、分辨率、帧映射和上述限制。
