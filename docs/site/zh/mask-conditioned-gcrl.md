# 视觉目标 mask 怎样进入 DexLab：先证明它是进度信号，再谈 GCRL

## TL;DR

**Dynamic Object Masks 的可迁移点，不是“再引入一种 GCRL”，而是让目标位置成为每步可检查的视觉信号，并在它进入策略或奖励前先过单调性、遮挡和误检门槛。**

它可能帮助 DexLab 把视觉接近、夹爪对位与物理接触拆开；它不能替代接触力、抓取成功或真机验收。论文报告了较强的 reaching 和 pick-up 结果，但仿真 mask 仍由特权位置与逐物体尺寸生成，真机训练也仍用预录目标位置终止回合。

## 从一个抓苹果任务开始

UR10e 需要抓住桌面上的苹果。若奖励只包含末端到苹果中心的 3D 距离，策略可以把夹爪停在苹果旁边：距离很小，但苹果没有落在两指之间。

Dynamic Object Masks 改为在 RGB 后追加一张目标 mask。普通 approaching 使用全图 mask 面积；抓取时只统计夹爪两指之间的 ROI。只有苹果进入可抓区域，mask overlap 才增加。双指接触后 mask 清零，奖励切换到接触、抬升和完成条件。

这个例子解释了机制：mask 不只是“目标类别”，也不只是“目标图像”，而是把目标在画面中的位置、尺度和与夹爪的几何关系同时暴露给策略。ROI 版本进一步把“目标看得见”连接到“目标放进了可抓窗口”。

## 哪个结果最有说服力

在 UR10e-MuJoCo pick-up 中，11 个 mask GC+reward seed 有 9 个在每类物体 50 次试验中超过 `90%`；3D position+distance 只有 2 个 seed 超过这一门槛。

视觉 reaching 的留出物体平均准确率更高：mask `99.9%`，3D position `98.9%`。差距只有 1 个百分点，最适合解释的是“mask 是有效接口”；它单独不足以证明表示机制必然优于特权坐标。

移动导航反而提供了一个平衡结果：mask 收敛更快，但最终低于始终拥有 3D 目标位置的策略。mask 策略必须先搜索目标再靠近，一旦目标不在视野内，它的优势就会下降。

## Grounding DINO 失败暴露了真正的测试点

Franka 真机从零训练中，Detic 策略完成 reaching；Grounding DINO 方案却因误检失败。错误框先进入 mask，mask 面积再进入奖励，策略于是更快优化 detector 错误。

用时间顺序写就是：

1. **初始条件／动作**：腕部相机观测场景，策略通过关节速度接近目标。
2. **状态／奖励演化**：detector 生成错误目标框，mask 面积被解释为进度。
3. **失效**：策略获得“接近目标”的奖励，但物理目标并未被接近。
4. **任务后果**：真机 reaching 失败。

最早失效层是视觉目标生成和 reward 语义，不是 SAC、接触求解或 sim-to-real。作者运行了这个真机案例；本轮只做了论文与固定源码核查，没有独立复跑。

论文没有报告 mask 缺失、闪烁、部分遮挡和面积抖动的受控消融。因此“detector 质量决定上限”有案例支持，但不同误差如何影响策略仍需测。

## Object-agnostic 的准确边界

仿真有 20 个已知物体，15 个训练、5 个留出。mask 由特权物体中心投影成矩形，并乘以每个物体预定义的宽高缩放和偏移。留出物体测试支持同一类别池内的实例泛化，不支持任意未知类别或任意几何。

作者也写明：它提供的是 object-agnostic **reaching** skill，不是 fully goal-agnostic manipulation skill。对杯柄、锅柄或剪刀把手，物体中心框仍可能不是正确接触区域。

另一个边界是“策略不读 3D 坐标”不等于“实验没有特权定位”。公开真机代码用预录 `target_pos` 计算末端距离，并在小于 `0.13 m` 时终止环境。actor 没有看到这个坐标，但 termination 与验收读取了它。字段用途必须分开记录。

## DexLab 应该怎样借鉴

### 直接借鉴

1. **给视觉进度信号写单调性合同。** 同一 episode 同时保存 mask 面积、中心误差、ROI overlap、真实距离和阶段事件，检查信号是否随任务进度变化。
2. **把检测失败单列。** 漏检、误检、延迟、框面积抖动和遮挡分别报告；不要把 `detector error → reward error → policy failure` 合成“训练不稳定”。
3. **区分 actor 输入与验收真值。** 最终评分可以使用可靠真值，但必须明确哪些字段从未进入策略。
4. **阶段判据必须分开。** 接近、夹爪对位、接触、保持、抬升和完成各自需要独立读数。

### 需要验证

先选 DexLab 已有的一条相机轨迹，冻结 20–30 个阶段点。对每个点计算目标中心投影、全图 mask 占比和夹爪 ROI overlap，再注入 20%–50% 遮挡、单帧漏检、误框和 1–3 帧延迟。

最低验收不是奖励更高，而是扰动后失败阶段没有被排到成功阶段之前，并能指出第一处视觉失效。若信号不单调，先修目标表示；若信号正常但策略仍不抓取，再检查 RL、接触和物理层。

### 暂不采用

- 不把 mask-size reward 当接触或抓取成功；
- 不把 `99.9%` reaching 外推到任意物体、相机或操作技能；
- 不因一个抓取案例新增通用 detector 框架；
- 不把渲染 mask 当成物理接触证据。

## 第一个可验证问题

**目标 mask 的面积与 ROI overlap，在遮挡、漏检、误框和延迟下，是否仍能把远距离、夹爪对位和接触前阶段排对顺序？**

这个问题不需要先训练 GCRL，也不增加物理后端。它只检验奖励读取的视觉信号能否成为任务进度的可靠代理。只有这一步通过，DexLab 才值得进一步比较视觉 GCRL、目标图条件与特权坐标条件。
