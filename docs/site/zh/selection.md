# 新场景的引擎与 solver 起点

先填写场景条件：接触尺度、物体质量与载荷、粘着／滑动、接触切换频率、几何复杂度、柔顺性与可接受成本。推荐的单位是**引擎核心／solver／运行路径／版本／有效配置**；同名 solver 或同一资产文件不足以证明等效。

| 场景特征与主要困难 | 有证据的候选起点 | 新场景首先验证 |
| --- | --- | --- |
| 小方块法向柔顺、加载卸载 | [法向经验](normal-response)：原生 MuJoCo 3.11 与 SuperDex 1.0 的冻结响应参数分别可复用；历史 PhysX 只支持其原协议解释。 | 有效刚度、质量／惯量、接触数与离面负载；不要直接把合成目标称为材料参数。 |
| 需要指定瞬态响应和较低成本 | [瞬态与成本](transient-cost)：MuJoCo 3.14 低阻抗配置是该合成目标的候选；完整参数和计时在报告。 | 振荡、无拉力、加载时刻与 native/观测成本；[迁移失败](mass-size-transfer)说明质量／尺寸必须重新验证。 |
| 斜面、支撑、低摩擦滑动 | [六引擎矩阵](coverage.md)：优先筛选相近工况下观测有效的配置，例如 PhysX 5.9 原生 PGS 开发基线。 | 静摩擦阈值、无摩擦对照、动量、加速度和旋转；最初通过率不构成等预算调参排名。 |
| 有限指面夹持、载荷／驱动受限 | [Genesis 力限额案例](pinch-load)，以及 MuJoCo 标准方块夹持记录。 | 每侧驱动与法向力、力矩、滑移、低力负例和释放；惯量修改另需 #145 准入。 |
| 复杂碰撞几何的机器人抓取 | [MuJoCo／SuperDex 14 s SDF 场景](https://github.com/huangkiki/Dexlab/blob/main/demos/apple-stem-grasp/README.zh-CN.md)，使用报告的完整资产、版本与控制。 | 碰撞几何准备、实际接触读回、完整抬升保持释放；历史单场景成功不等于新资产稳健性。 |
| 资产跨框架、CPU/GPU 路径迁移 | [匹配核心对照](framework-path)：先用 default/aligned 归因协议定位转换影响。 | 源资产、中间模型、最终参数、时钟、接触路径／容量、重置；版本匹配不了时不声称仅框架导致差异。 |
| 布料柔顺／自碰撞、推动、手内旋转 | [完整研究范围](coverage.md)与[后续路线](dexterity.md)。已有布料失败同样提供排查起点。 | 逐任务正例、负例与物理约束；未运行不是不支持，预折叠下落不是主动折布。 |

每次选型都保留候选配置、参数敏感性、物理误差、稳定性、成本、已测试迁移范围和失败条件。优先离线重评已有日志；仅补做无法由现有证据回答的最小实验。没有直接匹配场景时，明确“候选起点”，再冻结开发集和未见验证条件。

原生路径使用最新稳定版做新准入；框架路径使用官方兼容组合。旧版本仍可提供历史机制经验；匹配核心的归因实验与实际选型版本分别报告。资源瓶颈、安装成功和视觉回放都不能替代物理验收。

**LIBERO 起点：** [保留原生版本与配置，先核对观测时序](libero-workflow.md)。本轮没有通过验证的新物理配置；不要把 1 ms 当作通用修复。
