# 公开 AMP 抬箱：参考路径准备

**本例检验公开 G1 策略能否通过持续手部接触托起物体。DexLab 已准备输入、记录与诊断入口，尚无新的 AMP 原生结果。**

本例采用 [humanoid-amp-ppo 的 4889389 提交](https://github.com/shuayyy/humanoid-amp-ppo/tree/4889389118e0c88d3945dff54d2cd3f992ed815e)中的公开 `Mjlab-G1-DualArm` 权重和 Toaster003 模型。它与该仓库的 SuperMimic/PPO-Sim tracking 任务分别记录；不能套用 tracking 的 1.5 kg 箱体，也不能用 AMP 权重替代尚未公开的 tracking 权重。

## 已核实的输入与条件

权重和两段动作数据已固定 Git blob 身份并记录 SHA-256。任务引用的全部 35 个 G1 网格与 Unitree 官方文件一致；六个 Toaster003 视觉文件与 RoboCasa 归档一致。AMP 的 XML 额外加入自由根、抓取标记和显式惯性参数。原始动作采集及权重训练的数据来源尚未独立核实，DexLab 不打包外部权重和资产。

| 条件 | 公开 AMP 参考路径 |
| --- | --- |
| 模型 | 名义惯性质量合计 1.30 kg；保留启动时质量、质心和摩擦随机化 |
| 初始化 | 原始重置顺序，包含 25% 参考状态起始及 XY／朝向／关节随机化 |
| 控制 | 公开 actor 和原始裁剪；play 模式关闭虚拟 PD 与观测扰动 |
| 时钟 | 0.005 秒物理步，每动作四个子步，60 秒回合及原始自动重置 |
| 源端保持 | 单侧高度阈值与两个标记持续 0.4 秒；标记不证明接触承载 |
| 独立诊断 | 逐段统计无地面／其他支撑的双手有载接触；2 秒窗口与任务成功分别报告 |

候选使用官方 MuJoCo Warp 3.8.0.3，其运行时代码子树与锁定的 3.8.0.2 提交相同，在保留其余版本的同时解决 mjlab 元数据约束。原生兼容性和记录器一致性仍未验证。

## 入口与剩余验收

[案例 README](https://github.com/huangkiki/Dexlab/blob/main/demos/amp-box-lift/README.zh-CN.md)记录输入准备、两个独立进程探针、三个策略种子和配对的禁用手部接触负例。原生上限为六次启动、每次 900 秒、累计 5,400 秒；还须完成输入／运行时准入并冻结基于实测的资源方案。

选定显卡采用整卡占用 20,480 MiB 的采样停止阈值，并至少保留 2,048 MiB 空间。每 2 秒采样不代表测得瞬时峰值或设置硬分配上限。超限或无法读取遥测时停止本次工作，仍须保留最终资源证据。

离线夹具检查力解码、终止反馈、连续承载、地面／其他支撑拒绝、手部相对运动、动量跳变及负例质量不匹配。报告核验完整记录连续性并保留哈希。动量残差当前只计接触与重力；armature、广义力、其他约束和积分效应仍须归因。满足承载诊断窗口也保留 `task_success` 未定。

原生轨迹、完整物理资格和连续视频继续由 [#259](https://github.com/huangkiki/Dexlab/issues/259)承接，同时保留 tracking 与匹配比较义务。此次准备不增加跨引擎覆盖中的已完成任务数。
