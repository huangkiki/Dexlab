# UR7e＋CTAG2F90D 真机采集准备

[简体中文](README.zh-CN.md) | [English](README.md)

**当前结论：采集协议与离线格式检查已实现；没有真实测量结果，也没有已标定的仿真参数。** 对应 [D06 #33](https://github.com/huangkiki/Dexlab/issues/33)，数据进入 [#6](https://github.com/huangkiki/Dexlab/issues/6) 前另做测量质量审查。本实现只读取文件，不连接设备、不发送机器人动作。

## 研究问题与可识别范围

首项实验选**指定夹块／材料试样在规定加载方向上的准静态力—压缩量响应**。目标是测得系统的等效法向顺应性、加载卸载迟滞及重复性，给接触模型一个可复核的参考。力由独立参考测力元件测得，位移由独立位移计或经标定的观察系统测得。夹爪目标开度不能替代试样压缩量。

- 先以刚性参考件重复相同加载过程，量化夹具、指垫和测量链本身的变形。若无法分离，只报告整个接触装配的等效响应，不声称得到材料本构或唯一的刚度参数。
- 有可信力与位移参考后，可在预先选择的非零压缩区间拟合局部等效刚度 `ΔF/Δδ`；报告区间、残差、不确定性、迟滞，不能将任意非线性曲线压成一个全局刚度。
- 无外部力参考时，只能记录设置值—形变／保持／滑落关系。未知法向力时，仅凭滑落载荷不能唯一辨识摩擦系数；电流也不能自动换算接触力。
- 这是 UR7e＋两指夹爪的测量准备。相同材料的数据不能自动证明 OpenArm＋Wuji 的驱动、指腹或多指抓取精度。

## 已知设备与待补信息

用户确认两台 UR7e、两只相同 CTAG2F90D；只记录型号，不发布现场照片和设备序列号。左右夹爪分别校验，型号相同不等于零偏和传动映射相同。

厂家页面采用 **CTAG2F90-D** 的写法，列有 Modbus RTU／IO 以及位置、速度、力反馈；现场连接方式、固件、寄存器定义和力的测量原理仍须核实。网页标称重复定位指标不能用作本实验测量不确定度。[厂家型号页](https://en.changingtek.com/diandong/147)（查阅 2026-10-05）

UR RTDE 文档区分 `target_q` 和 `actual_q`，提供控制器时间、TCP 状态等字段；支持字段随控制器版本变化，负载时可能跳过输出包。因此保存实际配方和采样间隔，不用请求频率推定已收到的频率。[官方 RTDE 指南](https://docs.universal-robots.com/tutorials/communication-protocol-tutorials/rtde-guide.html)（查阅 2026-10-05）

| 现场核对项 | 应留下的证据 | 未取得时的处理 |
|---|---|---|
| 两臂／两夹爪固件、接口和驱动版本 | 人员核对记录、实际 RTDE 配方、对应版本寄存器文档及文件哈希 | `null`；不猜寄存器、比例或接线 |
| 开度定义和连杆映射 | 指端参考面定义；独立测量多个开度，包含加载卸载及重复 | 原始编码值保留，不当成米或指尖真实距离 |
| 夹持设置与反馈 | 原始命令、应答／状态、反馈字段来源、单位换算、量化范围 | 未核验反馈标 `unverified`；不可用标 `unavailable` |
| 独立力／位移参考 | 量程、分辨率、校准／核查方法、零漂、方向、安装与原始文件 | 缺一个就不做力—位移标定 |
| 工具／夹具与试样 | TCP／负载设置、夹块尺寸与材料、接触面、质量尺寸测法、材料批次与温湿度 | 保留未知，报告仅覆盖有证据的装配 |
| 录像与同步 | 连续近景原件、帧时间、共同同步事件、同步残差 | 不凭文件创建时间对齐；无法定量同步时仅作定性证据 |

## 同事可执行的采集顺序

本阶段不包含运动程序。现场人员沿用已批准的设备操作流程，先确定可执行的加载范围、速度与停止条件，并把实际数值写入冻结条件；模板不给未知夹具自动填力、速度或位移上限。

1. **接口核验。** 分别记录设备身份及字段文档。在允许的静止读回和既有操作中对照指令、反馈与独立测量；保留原始数据包及解码、单位转换说明。未知通道不能填零，不能复制命令冒充反馈。
2. **测量链核验。** 外部力／位移传感器空载置零、核查参考载荷和位移，记录预后零漂；定义正方向。以共同可观测事件估计各时钟到采集端单调时钟的偏移／漂移及残差。不确定度超过拟研究效应时停止拟合，先改善测量。
3. **开发试跑。** 刚性参考件和材料试样分别加载、保持、卸载，至少覆盖多个非零压缩水平；重复装夹，检查是否侧滑、姿态变化、饱和或夹具变形主导。仅用开发集选择加载区间、采样率、模型族和有效性判据。
4. **冻结采集表。** 在正式记录前列出全部试次、试样编号、材料批次、加载范围／速率／保持时长、左右夹爪、重复数与随机顺序；确定成功、异常和缺失的判据。开发、拟合和测试使用不同试样及完整工况组，禁止随机拆相邻帧。样本量由试跑方差与希望分辨的效应决定；模板的三个试次只是字段示例，不是充分样本量。
5. **正式采集。** 保存完整加载—保持—卸载及重新置零、连续近景与异步日志。每次重复有独立 ID；故障、饱和、丢包和中止都留下记录与原因，不能只交成功曲线。
6. **封存与交接。** 不改原始日志，另存转换脚本、版本、配置、哈希清单、冻结分组与校验输出。先检查文件格式，再由 #6 审查同步误差、传感器误差、有效覆盖和可识别性。测试集在模型和拟合方式冻结后才打开；若据此改模型，须另建测试集。

第一轮可以只测一侧夹具；未参与通道保留未知并不阻塞这一侧的数据准备。两侧测量单独分组，不把左右各一条曲线当作大量独立样本。后续夹持滑落、布料拉伸和完整任务复核需要各自协议；这里不预先宣称这些任务已验证。

## 时间、坐标系与误差

每条异步样本记录采集端接收单调时间 `host_time_s`、设备采样时间 `device_time_s`（未知为 `null`）、本通道试次内序号。设备时间和接收时间不等同；设备重启另建试次／时钟段，不跨重启拟合一条直线。保存请求采样率、实测间隔分布、缺失区间、时钟变换 `t_host = scale_to_host * t_device + offset_to_host_s` 的适用时段和残差。序号连续也不能证明设备没有丢采样。

每个坐标系要给出原点、轴向、正负号、量纲、测量方法和变换证据。左右机器人基座独立；未测相对位姿不能合成双臂空间数据。TCP 姿态采用平移＋旋转向量，不能按 Euler 角读取。指爪开度是明确定义的指垫参考面间距；压缩量需扣除接触前零点并声明是否包含夹具变形。

力／力矩必须同时说明参考点、表达坐标系、重力与工具负载补偿。UR TCP 合力不是两指各自的接触法向力。标称精度、数值分辨率、重复性和测量不确定度分别记录；`absolute_bounds` 是本次核验得到的逐分量绝对误差界，依据写入 `basis`，不是随手填的标准差或厂家宣传值。

## 可执行日志契约 v1

[准备模板](template/manifest.json)含四台已知设备及待选参考传感器；[样本文件](template/samples.jsonl)为空，**没有伪造测量数据**。复制整目录到新的采集目录再填写。命令在仓库根目录执行：

```bash
.venv/bin/python -m dexlab.hardware_log docs/hardware/template
# 准备模板返回 0：格式正确，报告未补齐项；不表示采集通过。
.venv/bin/python -m dexlab.hardware_log docs/hardware/template --require-measured
# 准备模板返回 2：尚非完整实测交接包；这是预期结果。
```

| manifest 字段 | 约定 |
|---|---|
| `schema_version`, `protocol`, `kind` | `1`、`ctag-contact-v1`；`preparation`／`synthetic`／`measured` 必须如实区分 |
| `devices` | 左右设备身份；固件和接口可为 `null`；外部参考传感器独立登记 |
| `artifacts` | 包内相对文件名 → SHA-256；保留原始源、解码／换算、标定／核查与冻结条件；不写私人连接信息 |
| `clocks`, `frames` | 语义和核验证据；时钟映射、误差可为 `null`；`evidence` 引用 `artifacts` |
| `channels` | `signal` 决定单位、维度及 `command/feedback/reference`；声明设备、源字段、坐标系、时钟、状态、核验证据及不确定度 |
| `trials` | 唯一 `id`；`split`、试样、工况、重复号、必需通道、实际条件、`planned/complete/aborted` 与中止原因 |

`samples.jsonl` 每行恰含 `trial_id, channel, sequence, host_time_s, device_time_s, value, quality, reason`。`value` 始终是数组（标量长度 1、关节／TCP 长度 6）；`quality=missing/invalid` 时必须是 `null` 且给出原因。`quality=valid` 仅允许已核验通道的有限数值。夹爪设置使用 `device_code`，只有核实转换的实际开度才使用 `m`。支持信号的完整单位和维度在 `src/dexlab/hardware_log.py:SIGNALS` 中；该模块即版本化的可执行格式定义。

校验拒绝命令与反馈源字段错配、单位错配、重复键、错误维度、非有限值、倒序／重复时间、分组泄漏、缺失／篡改证据、越出数据包的附件路径。报告缺失项、实际观察到的序号／无效样本缺口及试次状态；不插值、不覆盖记录。无效格式退出 1；普通格式检查通过退出 0；加 `--require-measured` 后实测种类或必需交接项不完整退出 2。仅必需通道及其测量链影响完整性；未用设备可以未知。

**边界：** 校验器不能从数字判断是否伪造，也不自动证明传感器标定、时间同步、足够采样、试样分组真实性或科学有效性。`measured_intake_ready` 只是文件交接条件，`scientific_acceptance` 始终为 `not_assessed`；中止与缺口不能删除来获得完整性标记。真实采集原件默认不公开，发布前另做隐私检查。

## 本地验证与剩余事项

日志校验器包含专门的合成回归测试。交付 PR 与 Release 记录确切源码树、完整单测、中英文档及原生仿真回归结果；仿真回归不能充当真机测量。未明确列出独立审查者时，审查为自审。

自动负例覆盖命令冒充反馈、未知填零、跨分组重复试样／工况、丢包、时钟回退、NaN、文件篡改、路径逃逸及准备／合成记录冒充实测交付。测试数据明确为合成数据，不是现场结果。

当前缺少现场固件／接口核验、独立参考传感器选型及误差、实际冻结工况和真实采集集。#33 交付采集准备，#6 负责后续实测与拟合；计划表中的“基础实测”在真实数据取得前仍未完成。
