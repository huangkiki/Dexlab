## 静态验证

在 E1 工作树执行：

```sh
git diff --check
python scripts/check_docs.py
python scripts/check_examples.py
```

结果：空白检查通过；仓库相对 Markdown 链接通过；1 个 Python 示例文件、2 个文档 Python 片段的 AST 通过，1 个 XML 文件结构解析通过。CI 增加同一 `check_examples.py`，只解析源文本，不导入 MuJoCo、不执行片段、不校验 MJCF schema。

源码身份检查逐个计算 Git blob SHA-1（`blob <byte-count>\0<contents>`），与固定官方 Git 树、[sources.json](../sources.json) 的 20 个文件对应；章节及源码地图中所有本引擎 blob 链接使用同一固定 SHA。行锚检查确认目标行存在，随后人工核对关联函数/字段/文档段落；行号存在本身不证明结论正确。

未做：Python import、MuJoCo XML 编译、forward/step、渲染、物理/性能实验、训练、跨引擎比较。没有生成运行输出，因此示例尺寸和行为预测明确标为推导。后续研究实验只复用 DexLab 的相应版本/工况证据。

## 本版本中必须保留的差异

| 易被旧教程带入的假设 | 已核对的事实与来源 |
|---|---|
| Physics state 只有 qpos/qvel/act | 3.15.0 加入 `history`；见 [mjtState](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/include/mujoco/mjtype.h#L527) |
| ctrl 长度等于 actuator 个数 | `nu` 与 `nactuator` 分开；见 [model 尺寸](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/include/mujoco/mjmodel.h#L246) |
| reset 后用户输入一律清零 | quaternion ctrl 由 `mj_resetCtrl` 写单位四元数；eq_active 使用模型初值，history 也有元数据；见 [resetCtrl](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/src/engine/engine_io.c#L1653)。simulation.rst 的概述未完整涵盖这些例外 |
| integration mask 是所有模式的完整快照 | sleeping 完整恢复需要 `mj_copyData`；IPC multiplier/age 明确不在 mask。见 [sleep notes](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/doc/programming/simulation.rst#L1386)、[IPC 字段](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/include/mujoco/mjdata.h#L249) |
| objectVelocity 返回平移在前 | simulation.rst 末尾有此陈旧文字；[公开 API](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/include/mujoco/mujoco.h#L632) 与[实现](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/src/engine/engine_core_util.c#L835)为 rot:lin，BODY 质心/惯性轴、XBODY body 原点/轴 |
| 所有 integrator 的 qacc 都是瞬时连续加速度 | `discrete` 的 qacc 是一步速度差除以 h；[计算说明](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/doc/computation/index.rst#L713)明确改变契约 |
| step1+step2 总等于 step | RK4 配置在 step2 路径调用 Euler；[实际分支](https://github.com/google-deepmind/mujoco/blob/9ea3cdfcae93bf2cc4dc0e1a1627c5a39a1e06e5/src/engine/engine_forward.c#L2125) |

这些差异已通过阅读固定源码确认；上游文档冲突没有在本任务中提交上游 Issue，也没有用运行实验仲裁。后续升级版本应重新检查，不能机械迁移这里的行号或枚举值。

## 完成后重新审视

E1 建立了后续必须共享的配置/状态/时间契约，没有发现阻止 E2 的外部依赖。建议下一项 E2：先从原生 actuator 结构区分 ctrl、activation、传动输出和广义力，再进入机器人 FK/Jacobian/IK 接口、控制更新与任务状态机。E3/E4 也依赖 E1，但分别交付接触数值机制和传感渲染，不在本项顺手写成完成。

等待项仅为本变更的集成发布流程；运行验证属于明确延后的工作，不是静态验收已完成的替代证据。E1 的自身审查由实现者完成，未冒称独立外部 reviewer 已批准。
