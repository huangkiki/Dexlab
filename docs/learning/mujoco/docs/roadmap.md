# MuJoCo autodev 路线

一个阶段对应一个可恢复的 GitHub Issue；总看板统一管理六仓，仓库保留本引擎的原生设计。先查同题 Issue/PR 和实际合入状态，再继续工作。

| 阶段 | 交付切片 | 依赖 | 状态 |
|---|---|---|---|
| E0 | 双路线导航与固定版本源码导读 | 无 | 首批导读已交付 |
| E1 | 建模、坐标、状态与时间专题 | E0 | [课程与静态验收已交付](validation/e1.md)；无运行验收 |
| E2 | 驱动、机器人与任务接口专题 | E1 | [课程与静态验收已交付](validation/e2.md)；无控制/IK/抓取运行验收 |
| E3 | 接触、求解器与力观测源码专题 | E1 | [课程与静态验收已交付](validation/e3.md)；无接触/数值运行验收 |
| E4 | 传感器、渲染与可视化专题 | E1 | [课程与静态验收已交付](validation/e4.md)；无传感/图像/headless运行验收 |
| E5 | 批量、学习接口与数据专题 | E2、E4 | [课程与静态验收已交付](validation/e5.md)；无批量/JIT/训练/数据生成运行验收 |
| E6 | 引擎特色、扩展与能力边界专题 | E3 | [课程与静态验收已交付](validation/e6.md)；无插件/形变/IPC/导数/设备运行验收 |
| E7 | A0完整安装、双路线课程审校与 DexLab 复用入口 | E2–E6 | 待开发 |

E0 交付的是导读与导航，不是所有专题。E1–E6 逐个展开目录中的知识点，E7 按完整课程契约审校。依赖必须以实际文档或合入提交核实，不能仅凭 Issue 关闭。

每个 Issue 记录目标、范围、先修、固定版本/来源、交付文件、易错点、验收命令和剩余问题。本轮验收为文档链接、源码/公式核对及最小片段的语法检查；明确区分未运行、源码核对和运行验收。无新实验、训练、性能基准、跨引擎框架或评分器。

有可执行任务时按依赖推进；阻塞时记录原因和恢复条件。没有用户要求不创建定时任务。研究数据与实验最终引用 DexLab。

E1 复盘：新增两篇专题和原创字段阅读片段；修正旧版教程常见的状态/控制/空间向量假设。当时确定的下一项为 E2（现已交付课程），从状态与控制的区别进入 actuator、机器人映射和任务接口。E3/E4 也在 E1 合入后具备前置条件；不以 E1 完成替代这些专题。

E2 复盘：新增执行器、机器人运动学与任务时序三篇专题，特别核对 3.15 的多输入/多输出驱动与限幅语义。下一项建议 E3，沿 actuator 广义力与物体接触力的区别展开碰撞、约束、metric 与力观测；E4 也已具备 E1 前置条件。E5 仍需 E4，不能只因控制接口完成就开始宣称学习数据闭环已交付。

E3 复盘：补齐 B0 动力学并展开 A4/B1–B5，重点修正旧版 margin/gap、CG/PGS 算法、惯量存储与净接触力假设。下一项建议 E4，建立完整传感器/渲染接口后才能进入 E5 的学习与数据课。E6 的 E3 前置也已具备，仍需独立展开 flex/IPC、插件及后端，不能只凭兼容性表宣称完成。

E4 复盘：新增传感与采样、相机/几何查询、渲染/viewer三篇，核对3.15的history、触觉通道、相机路径差异及classic/Filament接口身份。下一项建议E5，E2与E4的课程前置已具备，仍须主审发布后另行派发；E6的扩展实现不由本轮概览替代。后续数据和实验采用DexLab证据边界，不新增benchmark。

E5复盘：新增CPU批量、MJX与设备、学习/随机化、记录/回放四篇，沿固定源码核对ctrl=None、warning填充、多模型兼容性、后端/容量、PRNG与state mask边界。下一项建议E6，E3前置已具备，继续插件、flex/IPC与完整扩展实现；必须由主审验收发布后另行派发，不把本轮设备边界讲解当作E6完成。无新增实验或benchmark。

E6复盘：新增插件/回调、flex、IPC、后端/可微、多物理/源码综合追踪五篇，逐段核对当前接口与旧文档冲突、AL/CCD部分推进日志、JAX外层循环、Warp history初始化和fluid added-mass实际分支。下一项建议E7：E2–E6前置已具备课程内容，补齐A0完整安装/构建与全路线审校、DexLab证据入口。需由主审发布后另行派发；E6不自行启动E7，也未开展安装/原生运行或实验。
