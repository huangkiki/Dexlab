# 有界自动研究：交付链审计

[English](autonomous-delivery.md) | [简体中文](autonomous-delivery.zh-CN.md)

本报告核验 **#32 的实际研究交付、#31 的公开离线复算，以及独立注入的进程中断恢复**。三者分别提供证据；不把故障注入说成实际物理实验崩溃，也不把自动交付成功说成物理模型准确。

## 中断恢复：实际进程故障注入

[机器可读结果](evidence/recovery-exercise-v1.json)对应一个独立的小型恢复夹具。受限服务强制 8 GiB 内存、一个 CPU 配额、32 个任务、120 秒时限和零 swap；它不是吞吐测试。

1. 启动 guard 及等待释放信号的前台子进程，保存 active 记录。
2. 只杀死 guard，实测仍有一个存活子进程。第二个执行请求返回 75，命令标记未创建、未生成伪完成回执。
3. 释放原子进程并确认该进程组无活跃成员，才尝试恢复。
4. 恢复返回 0，回执关联原窗口；原始夹具文件 SHA-256 前后一致，原中断记录保留。

外层启动进程收到的退出码为 247：内部 guard 的信号退出经 Python 退出状态传递得到该值；不能把它解释为实验正常结束。外层受限验证服务最终退出 0。

回归复现使用 `tests/test_research_guard.py` 的 `test_killed_guard_keeps_live_child_group_blocked_then_recovers`；新增断言同时检查旧回执未改写和夹具哈希不变。在已通过资源准入、持有研究互斥窗口的环境中运行：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_research_guard.py' -v
```

此测试只验证前台进程组契约，不覆盖进程逃逸、跨主机网络分区、断电持久性或大归档损坏；也不证明宿主定时器一定唤醒。任务领取资格和依赖另由 `tests/test_autoresearch.py` 覆盖。部署路径、账户和私有回执不进入公开报告。

## 版本与研究边界

历史批次保持冻结。新派发、批次冻结和发布前继续执行[版本准入](engine-qualification.zh-CN.md)；发现更新则记录旧运行，不能在运行中换环境或重贴版本标签。Genesis 的执行仍由 #42 的实际依赖和资格控制，本报告不宣称已支持。

这里证明的是一个有界、可追溯的研究交付实例与指定恢复行为。物理有效性仍须依据[研究标准](research-focus.zh-CN.md)分别评价，#10 的接触机制问题和 #6 的实测校准不会因 #35 工作流验收而关闭。
