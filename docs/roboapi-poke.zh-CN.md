# Poke RoboAPI 适配与 sim2real 对照

DexLab 的 Poke RoboAPI 适配层把策略调用与具体仿真任务解耦。任务侧负责采集真实可部署的观测并把动作映射回控制器；适配层只负责模型发现、会话、动作协议和回执，不私藏 key，也不替代真实机器人安全逻辑。

## 已实现

- `RoboApiClient`：`GET /models`、`GET /models/{id}/schema`、`POST /sessions`、`POST /chat/completions`、`POST /sessions/{id}/close`。
- `PokeSession`：维护 `session_id`、`next_turn`、上一轮 assistant 消息和 tool 回执，下一轮请求不会丢失执行历史。
- 输入校验：8 维状态、归一化 xyzw 四元数、夹爪 `[0,1]`、PNG/JPEG 图像。
- 输出校验：非空动作块，每行 8 维，有限数值，四元数归一化，夹爪范围容差。
- `inspect.py`：`models` / `schema` / `infer` 三个只读或单次推理命令。

API key 仅从 `POKE_ROBOAPI_KEY` 读取，不写入日志、配置文件或仓库。

## 观测与动作契约

| 字段 | 真实/仿真约定 |
| --- | --- |
| `instruction` | 与任务画面一致的自然语言指令，长度受模型 schema 的 `max_chars` 限制 |
| `state` | `[x, y, z, qx, qy, qz, qw, gripper]`；位置为模型任务坐标，单位米；四元数为 `xyzw`；夹爪 `0` 闭合、`1` 张开 |
| `image` | 腕部 RGB PNG/JPEG；保留原始宽高比和鱼眼畸变，不裁切、镜像、旋转或去畸变 |
| `output` | `(T, 8)` 绝对目标，以 30 Hz 派发；T 由响应决定 |
| 控制点 | 法兰安装面中心，不是夹爪尖端、抓取中心或相机中心 |

## 真实本体与仿真本体对照

| 维度 | 真实本体 | 仿真本体 | 必须保持一致 |
| --- | --- | --- | --- |
| 机械臂/夹爪 | 例如 UR5e + Robotiq 2F-85 | 对应 URDF/USD、关节范围、法兰定义 | 关节身份、控制频率、夹爪开合方向和法兰中心 |
| 相机 | 例如 Insta360 Ace Pro 2 + 极广角镜头 | 相同相机位置、朝向、视场和畸变 | 夹爪在画面中的位置/占比、鱼眼畸变、亮度 |
| 状态坐标系 | 由 Home + A/B/C 三点标定建立 | 同一任务坐标和姿态轴 | 位置、`xyzw` 顺序、控制点、工作空间边界 |
| 动作接口 | 30 Hz 绝对目标，逐步执行回执 | 同频率、同绝对目标语义 | 实际派发步数、越界裁剪、真实状态回读 |
| 物理对象 | 真实质量、惯性、材料和摩擦 | 冻结模型与接触参数 | 不是只对数值，还要记录单位和来源 |
| 渲染 | OVRTX 可选高质量 RGB | 同场景、材质、灯光和机位 | 渲染不得改变物理状态或评分 |

## 传感器配置

适配层只传递 RGB 图像和 8 维状态，因此仿真必须提供与真实部署同语义的腕部 RGB 观测。以下是准入清单：

- 相机外参：控制点与相机原点和光轴关系固定；
- 内参与畸变：保留鱼眼，不把广角相机替换成普通透视相机；
- 分辨率：按 schema 缩放，默认 1280×720 → 640×360，等比、不裁切；
- 帧同步：图像与 `state` 来自同一时刻；
- 亮度与视野：夹爪、目标和桌面轮廓清晰，无大面积过曝或暗部丢失。

## OVRTX 渲染层

OVRTX 用于高质量 RGB/合成数据回放，不负责物理。物理步进仍由原生 MuJoCo、SuperDex、Newton 或 TLMPM 执行。使用 OVRTX 时必须：

1. 保存原始物理状态和相机时间戳；
2. 用同场景、材质和灯光恢复画面；
3. 只渲染保存状态，不插值顶点、不推进物理；
4. 记录帧到状态索引的映射、输入/输出哈希和渲染成本；
5. 明确它是视觉证据，不是新的传感器保真度或吞吐量结论。

## 代表性任务的 solver、参数与阈值

下表说明当前证据中的实现身份。尚未接入 RoboAPI 的任务仍需要逐任务观测/动作映射；表格不是“已跑通”的模型成绩。

| 任务 | solver 与版本 | 关键参数/实现 | 冻结阈值 | 渲染与 RoboAPI 状态 |
| --- | --- | --- | --- | --- |
| Wuji 双指夹球 | MuJoCo 3.17.0 CPU，SDF，implicit-sampled-PD | 20 g 球，v4 合成抗扭接触，步长/控制周期来自 protocol | 两秒保持位移 ≤ 2 mm，主动释放，负例 | MuJoCo 记录回放；RoboAPI 执行映射待接入 |
| 苹果抓梗 | MuJoCo 3.11.0 / SuperDex 1.0.0 FP64，SDF–SDF | OpenArm 双臂 + Wuji，已知位姿、IK、脚本关节目标 | 14 s 抓持、间隙、两指连续支撑、穿透、动量平衡 | MuJoCo 记录/OVRTX 回放；RoboAPI 映射待接入 |
| 海绵擦拭 | RSS 固定 `23417de`；Newton 1.6 / MuJoCo/MJWarp 3.12 / SuperDex 1.0 FP32 | latch 柔顺辅助、60 Hz、16 刚体子步、2 SuperDex 步 | 清洁率 ≥ 90%、峰值力/压力、归位误差，无辅助对照保留失败 | tiled + OVRTX 回放；RoboAPI 映射待接入 |
| 切割/推动 | CPU TLMPM，BladeMaster 参考 | 合成材料、黏性、半步长、无推对照 | 各切割报告冻结的分离/连通/接触力阈值 | OVRTX 表面回放；RoboAPI 映射待接入 |
| 布料 | MuJoCo / SuperDex / Newton / Genesis，任务相关 | 下垂、拉伸、覆盖、预折叠下落、夹布分开验收 | 各报告独立协议，保留穿透和失败 | 部分 OVRTX 回放；RoboAPI 映射待接入 |
| 接触基准 | MuJoCo / SuperDex 等 | 斜面、法向、冲量、阻尼、质量尺寸迁移 | 解析/工程参照和固定分母 | 静态图表；RoboAPI 映射待接入 |

每个数字的适用版本、场景和验收条件以对应报告为准。更换模型、仿真器、控制器或任务协议时，必须创建新 cohort，不能复用旧分数。

## 边界

- 适配层已验证的是 HTTP 协议和会话状态，不是真实机器人安全性。
- `completed` 只表示动作块已派发并完成执行周期，不表示物体已经抓住或任务已经成功。
- 仿真通过不证明真机成功；OVRTX 回放不证明传感器保真度。
- 正式榜只接受 DexLab 官方执行并通过反刷榜检查的结果。
