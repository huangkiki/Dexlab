# UniSim 复用：标准方块任务的准入边界

当前结论：隔离 FP64 候选通过下述标准方块有限对照，但未消除生产代码重复，完整独立接触账本仍需原生访问，因此保留生产场景原生所有权。以下旧版适配器审计为历史失败证据，不用后续候选结果改写其结论。

## 历史发布版准入拒绝

当时的决定：当前 FP64 标准方块实验继续由原生代码创建和管理场景。仅改版本限制不能保留任务语义。该阶段是实测准入拒绝；后续候选物理对照见下文。

## 证据

检查的 UniSim 1.7.10 源码提交为 `dc41b5e79d58d9b58eba9b2f27d10d71e16cf03d`。未修改的加载器要求 Genesis 1.3.3，在创建场景前拒绝已安装的官方 Genesis 1.4.3。随后，隔离诊断直接向原初始化函数传入原生模块，**仅绕过已失败的加载入口以观察初始化**，不视为后端准入。

实际读回：原生浮点类型 `torch.float32`，适配器张量缓存 `torch.float32`，NumPy 缓存 `float32`。没有创建场景或执行物理步；没有修改引擎或依赖检查。证据来自真实初始化与缓存分配，而不只是空数组占位类型。

## 对当前任务的逐项检查

| 方块协议要求 | 所查适配器行为 | 影响 |
|---|---|---|
| 官方 Genesis 1.4.3 | 加载器精确要求 1.3.3 | 发布路径在建场景前拒绝 |
| CPU FP64、确定性 seed 0 | 初始化不传精度/seed，有 GPU 时自动选择 GPU | 不保留冻结初始化 |
| 全精度位置目标 | step 转换为 NumPy float32 | 仅改初始化仍不足 |
| FP64 实测状态与接触记录 | 实际缓存分配为 torch.float32 | 输出精度须单独验证 |
| 步长、重力、椭圆摩擦锥 | 有显式构造选项 | 仅源码支持，未证明实测等价 |
| noslip=0、指定接触时间常数 | 公共构造参数不含 noslip，任务原生设置仍需追踪 | 不能声称默认参数相同 |
| 双侧逐步接触力与穿透 | 有精确几何对的合力聚合，后端未找到穿透字段 | 合力不等于完整独立验收记录 |
| 独立进程重复、场景重置 | 存在会话生命周期限制与重置方法 | 实际重置/接触状态等价尚未测量 |

源码定位：`src/unisim/backend/genesis/dependencies.py::load_genesis_dependencies`、`materialization.py::init_genesis_session` 和 `build_genesis_scene`、`backend.py::_make_device_cache`、`step`、`_read_portable_contact`、`reset`。结论针对所查版本，不概括所有适配器。

## 收益与剩余范围

已证实消除的任务代码：**0 行**；已迁移任务路径：**0**。这是实际交付计数，不是预计节省，也不证明适配器普遍无用。目前套用适配器会先增加兼容、精度与观测工作，尚未获得可量化的删减收益。163 行原生 runner 继续拥有场景；独立评分与记录协议无论采用哪条路径都要保留，并不声称这 163 行均不可简化。

不得以 FP32 替换实验冒充 FP64 协议准入。兼容候选必须显式保留执行设备、初始化、控制与缓存精度、完整原生接触、参数读回和重置语义，再冻结并执行接触对照、量化减少的重复代码。迁移 SDF 路径仍需完整门禁。下述候选补齐了成对实验，但未证明生产代码删减收益；不放宽 #47 的原生 PhysX 限制或 #6 的实测数据要求。

## 成本与限制

恢复安装完成耗时 5.867 秒，隔离初始化/缓存诊断 11.849 秒；经过实测资源准入，cgroup 限制为 24 GiB、两核等效 CPU、128 进程，禁用 swap。更早的中断安装及失败另行保留，这两个时长不是项目历史总成本。初始化不能支持速度、任务成功或真机精度结论。CPU Torch 发行包避免为 CPU 诊断下载无关 CUDA 组件。

## 复现诊断

[机器可读结果与模块哈希](evidence/unisim-reuse/reproducible-boundary.json) 绑定了安装源码与包版本。在安装所查源码的隔离、资源准入环境内，通过文档要求的有界执行器运行 `python scripts/probe_unisim_genesis_boundary.py NEW_OUTPUT.json --initialize`。脚本拒绝覆盖证据；即使诊断退出码为零，`loader.accepted=false` 仍然表示拒绝准入。脚本有意调用适配器私有缓存函数，未来 API 变化可能使诊断失效，不代表兼容成功。

第二次可复现诊断耗时 4.252 秒，确认相同类型。静态 AST 检查发现 backend.py 中 52 处、materialization.py 中 19 处显式 float32 属性引用，包括本次未执行路径。这是改动范围线索，不是 71 个已实测故障，也不是批量替换清单。精度兼容需要逐路径与共享辅助函数审核，不应盲目替换。该历史诊断未应用兼容补丁。

## 候选适配器范围

隔离且尚未提交的 FP64 适配器候选已通过任务控制与接触力缓存精度的针对性检查。保留既有导入、参数、非零状态复位及短接触准入证据；这些不等于任务配对等价。下文记录了已完成的四次固定控制对照。生产场景仍由原生路径持有，待运行对照与实际工程收益决定是否接入。候选的多环境通用测试目前因其显式单环境限制而失败。

## 固定控制候选结果

候选四次运行（夹持与张开负对照，各含复位重放）完成32,000个物理步。独立对照通过冻结数值阈值：位置最大差1.773e-14 m、速度差1.649e-12 m/s、净接触力差2.012e-9 N。记录中的公开状态和配对力读数与原生账本完全一致；四次运行也均通过既有穿透、动量、保持/负对照及释放检查。[配对评分](evidence/unisim-reuse/paired-score.json)、[物理检查](evidence/unisim-reuse/physical-score.json)。

这仅是隔离补丁候选的单环境资格，不代表已发布适配器通过。严格配置相同检查先失败；原生零步审计确认默认值展开及两个显式批量存储差异，后续存储表示对照保留差异且未改变数值阈值。原失败证据保留。原生历史轨迹直接复用，一个张开负对照基线用于两次候选复位重放；不能据此宣称真机精度或跨机器性能优势。生产任务迁移0条、实际消除生产重复代码0行；穿透及完整力账本仍需原生访问，因此在证明维护收益前继续保留原生场景所有权。

## 复现材料

[候选补丁](evidence/unisim-reuse/unisim-fp64-candidate.patch.gz)针对 UniSim 提交 `dc41b5e79d58d9b58eba9b2f27d10d71e16cf03d`，[来源记录](evidence/unisim-reuse/candidate-provenance.json)绑定哈希。先以 `gzip -dc unisim-fp64-candidate.patch.gz` 解压并管道传给隔离检出中的 `git apply`，并通过 `PYTHONPATH` 选择该目录的 `src`。补丁仅改变 Python 适配层；官方 Genesis 1.4.3、Quadrants 1.3.3、MuJoCo 3.15.0 的资格单独核验。

在资源限制包装器下执行 `scripts/run_unisim_pinch.py NEW_OUTPUT --reference docs/evidence/unisim-reuse/reference.json`。[初态参考](evidence/unisim-reuse/reference.json)分别保留历史选项与零步审计的实际解析选项。执行 `scripts/score_unisim_pinch.py NEW_OUTPUT NATIVE_CAMPAIGN_ROOT NEW_SCORE.json` 比较时会校验原生轨迹哈希；原生目录必须含 Issue90 三个原始 attempt 目录，小型参考 JSON 不能替代原始轨迹。复位读数在新控制前采集，之后仅重放动作，不注入逐帧状态。

本次进程耗时52.908秒，导入后47.761秒，使用24 GiB内存/两核CPU/128任务硬限制、禁用swap。该值为带观测记录的成本，不与历史原生运行作速度排名，也不含旧准入、安装和失败尝试。通用多环境测试仍与候选的显式单环境限制不兼容；不声称GPU、软体、任意材料或真机能力。

[综合评分](evidence/unisim-reuse/combined-score.json)同时调用既有独立物理评分，并直接比较候选复位重放。两种工况的重复运行在已记录状态与力上差异为零。公开评分命令执行这三类检查。
