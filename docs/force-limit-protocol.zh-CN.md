# 夹持力限额失效边界：实验预登记

研究问题：逐指驱动力限额如何改变方块的持续保持，结果能否延续到两个冻结的侧向初始偏移？[清单](../demos/contact-benchmark/force-limit-v1.json)在观察结果前固定16个回合。本页保留运行前协议；已完成的执行见[结果报告](force-limit-results.zh-CN.md)。

复用已验证的[原生方块夹持任务](../demos/contact-benchmark/GENESIS_PINCH.zh-CN.md)。仅改变对称逐指力限额（0.2、0.4、0.8、10 N），以及评估时的初始横向位置（−2、+2 mm）。开发集6例，含10 N独立进程重复与空夹负例；评估集10例，含8个夹持与2个空夹负例。评估前冻结控制器、执行器和评分代码，不训练、不逐例调参。

驱动力限额不等于实测接触力。理想对称平面夹持的静态估算 mg/(2μ)=0.62784 N/指仅在准静态双侧接触假设下成立，用于诊断，不作为驱动力失效阈值或验收判据。记录原生接触力向量；投影法向力须标明几何假设。瞬态、接触几何与数值失败均可能否定该解释。

保留原有1 mm穿透、1e-8 N力账一致性、5%重力冲量残差阈值。2–3 s保持窗口内质心始终≥60 mm、两侧接触均有效、其他支撑≤0.01 N；3.8–4 s释放窗口内质心≤30 mm、夹指接触力模长之和≤0.01 N。数值有效性与任务成败分别报告，并给出首个失效采样。空夹负例始终不高于30 mm，保持窗口不得出现夹指有效接触。

每例独立进程，读回初态与参数；失败及不完整记录全部保留。计划16例，含仪器修复重试最多24次；单次调用最长30分钟，原生执行累计最长3小时。一个通过准入的cgroup执行者、零swap；测速时停止传输与哈希。分别记录准备、编译、控制、步进、读回、评分、渲染和总耗时。

交付全部逐例结果、实际状态近景回放、力/高度曲线与原始证据。固定挑战集不用于推断总体成功概率，不宣称真机精度、学习/视觉控制或引擎排名。#6真机标定仍待实测，本项也不完成#3。完整验收见[Issue #90](https://github.com/huangkiki/Dexlab/issues/90)。

## 复现入口

使用[执行规则](autoresearch.zh-CN.md)规定的准入环境与有界调用。每例独立进程，输出到配置数据盘上的新目录。在该受限调用内执行，例如：

```bash
python -m dexlab.genesis_pinch_probe OUTPUT --case-id dev-cap-0.2
python -m dexlab.genesis_pinch_score OUTPUT
```

Schema-2评分先校验清单快照、工况身份与经审查执行源码字节，再评分原生记录。该溯源检查支撑源码审核，不能证明任意不可信JSON从未伪造；原始力账、动量检查和全速率记录仍不可缺少。评估期间保持执行与评分源码冻结。
