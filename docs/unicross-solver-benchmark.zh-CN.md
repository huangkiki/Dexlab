# UniCross 对 DexLab 的启示：跨技能接触诊断

[English](unicross-solver-benchmark.md)

**状态：研究提案，尚未实施。** 本文不代表已复现 UniCross、运行策略或完成跨引擎测量。

## 参考与研究价值

- [UniCross 项目](https://zdchan.github.io/UniCross/)研究抓取、搬移、手内旋转和手内平移等灵巧操作的统一表达。
- DexLab 已开展接触/摩擦、夹持稳定性、参数敏感性和求解器适用性研究。新增价值不是再做一次成功率排行，而是把孤立的接触诊断扩展到**连续技能中的接触模式切换**。
- 现有[灵巧操作路线图](dexterity-roadmap.zh-CN.md)已规划多指手内旋转（#48）。本提案补充该方向，不重复承诺已实现的能力。

## 核心研究问题

1. 从抓取过渡到搬移、旋转或平移时，最先失效的接触机制是什么？
2. 能否将独立评分发现的失败定位到碰撞几何、接触生成、摩擦/滑移、约束收敛、步长、驱动执行或策略不匹配？
3. 在明确的物体、载荷、接触条件和计算预算下，哪些已验证的 Solver 配置更可靠？

## 建议的有界实验协议（未执行）

1. **资产与许可审查：** 先确认上游代码、模型、策略/控制器、版本和许可证是否可获取。若不可用，仅构建原创的最小任务协议，不声称复现 UniCross。
2. **冻结场景：** 先做抓取保持与可控的手内旋转/接触切换探针；独立验收后再扩展平移和搬移。实验前冻结几何、质量惯量、初态、命令轨迹、步长/预算、评分窗口和失败判据。
3. **物理层探针：** 在支持时重放固定**控制命令**，而不是注入状态；记录物体位姿、首次滑移/掉落时刻、接触持续性、带时间归属的法/切向力或冲量、穿透、可观测残差、步长/容差敏感性和运行成本。缺失观测必须明确标记。
4. **任务层评测：** 独立统计任务完成、掉落、非预期运动和恢复；区分固定控制器跨引擎迁移与各引擎重新训练。未审计驱动、接口及接触模型语义前，不把差异单独归因于 Solver。
5. **覆盖与证据：** 遵循[研究定位](research-focus.zh-CN.md)、[任务覆盖计划](task-coverage.zh-CN.md)及 [AGENTS](../AGENTS.zh-CN.md)。冻结适用的六引擎及 Solver 配置矩阵，逐格保留通过/失败/阻塞/不支持/未运行状态；复用已验证历史证据，但不冒充新实验。
6. **诊断输出：** 对每个失败给出首次分歧事件、竞争假设、单因素消融、证据不确定性和条件化的 Solver 选型建议。解析校验和数值自收敛不等于真机验证；没有同条件实测就不能宣称真实物理精度。

## 建议交付物

- 带版本的引擎无关任务/接触阶段定义及两个最小探针。
- 独立评分器、原始轨迹、负例控制和缺失观测清单。
- 场景到失效机制的诊断表，以及附带失败与成本的条件化 Solver 选型建议。
- 评估扩展 UniCross 技能组合是否能提供超出现有 #48 的新信息。

## 非目标

不做缺乏物理依据的引擎排行榜，不宣称普遍优越性，不在本阶段训练策略或进行真机校准，不将不可用的上游代码描述为已复现。本文不包含实现或实验结果。
