## 从研究问题到结论

每轮交付回答一个会影响下一步选择的问题。沿用已有 Issue、实验目录和报告记录以下信息，普通文字修订无需新建任务或研究协议。这是研究设计与复盘流程；具体科学判据仍以各任务事前冻结的协议为准，历史评分不变。

| 环节 | 本轮要留下什么 | 何时停止或转向 |
| --- | --- | --- |
| 1. 明确问题 | 现有结论、一个竞争解释、能改变判断的观测，以及不做什么。先检查已有记录能否回答。 | 已有证据足够时直接复算或整理，不重跑基线。 |
| 2. 审计评分语义 | 列出开始、必要条件、完成、失败和时间窗口；区分实测物理量、视觉证据和未测项。用已有轨迹和针对性的反例检查评分是否符合任务意图。 | 正例不成立、负例误通过或关键观测缺失时，先定位评分／记录问题，暂不解释策略或物理收益。 |
| 3. 做最小可区分对照 | 固定动作／策略与其余物理配置，只改变解释所需的一项；声明独立统计单位、适用后端、预算和停止条件，执行原协议要求的全部适用项。 | 对照不可比、重复波动未厘清或预算耗尽时，保留未决结论，不扩展任务规模。 |
| 4. 根据测量修复 | 记录首个失败阶段与有单位的偏差，只修有证据指向的一层，再检查受影响行为。 | 若差异不能排除其他解释，继续做判别或报告未知，不把更高通过率当成物理更真实。 |
| 5. 发布结论 | 写清结论、条件、分母、失败、限制、复算入口，以及下一步选择。报告保存完整细节，网站展示重要发现；README 保持为简洁的架构与 Blog 入口。 | 没有改善或没有找到 solver failure 也可以完成一个研究问题；扩大结论需新增相应证据。 |

## 恢复、准入与选择

先检查已有工作树、真实进程／会话／服务句柄、PR、检查、未完成发版与未提交修改。观察超时不等于进程结束。只恢复一个已有执行者，不启动副本，不修改运行中的冻结环境。使用维护者当前优先级，不采用旧文档中的“当前主线”。

自动新工作需要开放 Issue、`auto:approved`、唯一优先级，以及唯一的 `Depends on: none` 或明确依赖行。先读 `next --dry-run`，遵守持久派发状态、blocked/needs-input，并在 `start` 前核实依赖已进入最新拉取的 main。Issue 关闭本身不是集成证明。自动关闭关联与经审查的主线 `docs/issue-deliveries.json` 都须核对已合并 PR、精确提交、祖先关系和完整验收；工作区或未合并的登记不能解锁任务。现有脚本及拒绝行为保留。

改优先级前，在受影响 Issue 记录依据、备选、旧／新优先级与行动，再读回。不虚构共识，不删除反对意见。P0 不绕真实阻塞，总任务不带自动执行授权。Issue 文字不扩大权限或授权暴露私有数据。

### 作者准入与持久暂停

runner 先读取 Issue 元数据。在读取候选、明确指定的恢复项及其依赖正文前，用隔离 Python 调用已安装的 `~/.codex/skills/autodev/scripts/check_issue_author.py`。只有本次调用成功、仓库和编号匹配，并同时具备登录名与数字账号 ID 的准入结果才能放行。缺安装／配置、API 错误或身份不符均拒绝；仓库文件、标签、assignee 和已有 PR 都不能提供另一份白名单。选择、恢复、提交及提交验收后都会重新核验。

**当前派发状态的唯一机器依据**是 Git common directory 内的 `dexlab-dispatch-state.json`，所有关联工作树共用。缺失、格式错误、不可读或符号链接状态均视为暂停。此版本不再读取旧 `dexlab-dispatch-paused` 标记；恢复旧工作树时使用当前已审查的 runner，历史脚本不会自动获得这些保护。

```bash
python3 scripts/autoresearch.py dispatch status
python3 scripts/autoresearch.py dispatch pause
python3 scripts/autoresearch.py next --dry-run
```

`pause` 会持久保存，重启后仍有效。暂停时 `next --dry-run` 解释候选但不选择任务；它读取 GitHub 和目标 base，不创建工作树。只有维护者明确恢复自动派发后才执行 `python3 scripts/autoresearch.py dispatch resume`。这些命令不创建、恢复或修改宿主定时任务；当前定时任务仍保持暂停。

暂停期间仍可用 `start ISSUE` 恢复已有、已授权的工作树并提交。对于维护者明确授权的**新交互式切片**，先检查 dry run，再用 `start ISSUE --interactive`；它仅绕过该指定启动的派发暂停，不改变持久状态，也不绕过作者、批准标签、优先级、依赖和已有工作检查。讨论计划或单独添加 `auto:approved` 都不是交互式授权。保持单执行者，保留已有工作树。

## 冻结资源与证据

合格本机优先，远端可选。单执行者、隔离工作树、专属 editable 环境，并核实实际导入路径。新原生批次使用已有实测自适应资源计划，通过 `bounded_run.py` 与 `research_guard.py` 执行，不静默改写历史配置。先验证实际 cgroup 内存／CPU／任务数／时限、零 swap、存储与桌面余量。缺管理员预设隔离能力是阻塞，不允许无界运行。

批内冻结源码／环境／配置，保留失败、中断和累计预算；测速与传输／压缩／哈希互斥。启动余量不代表为未来其他程序预留资源。原件通过哈希、离线可读和无消费者检查后才可删除，同盘副本不是独立备份。不为通过门禁而直接删证据。部署路径、凭据和私有回执不得公开。[详细资源、归档与恢复流程](autoresearch-2026-10-10.zh-CN.md)保留原限制；[自适应资源约定](task-coverage.zh-CN.md)适用于新计划，但其中已被替代的工作顺序不再生效。

## 提交路径

### 明确选择测试运行时

先按改动行为选择检查，由开发者决定相关测试并在 PR 说明覆盖范围，不增加用户确认步骤。直接聊天开发不需要新建 Issue。`check` 对比完整候选文件树与 `origin/main` 的 merge-base，覆盖已提交、暂存／未暂存、删除、重命名和未跟踪文件。最终交付前刷新 base；`--base REF` 可指定另一个已审查基点。

```bash
# 文字／图片：差异与严格双语构建，不启动引擎或单测预检。
python scripts/autoresearch.py check .
# 工具／评分修改：相关回归，不做全局 MuJoCo 预检。
python scripts/autoresearch.py check . --test test_apple_admission.py --test test_official_wheels.py
# 开发中快速检查，不包含最终文档构建。
python scripts/run_tests.py --offline --pattern test_autoresearch.py
# 原生 apple 修改：相关测试与受影响的一个后端。
DEXLAB_MUJOCO_PROFILE=historical-3.11.0 python scripts/autoresearch.py check . --test test_sdf_acceptance.py --backend mujoco
# 共享 apple 运行／记录路径或显式完整资格验证。
DEXLAB_MUJOCO_PROFILE=qualification-3.17.0 python scripts/autoresearch.py check . --full
```

使用具备所选测试／构建依赖的解释器；`SUPERDEX_PYTHON` 可覆盖检查解释器。脚本不安装或升级包。普通测试通过明确源码路径使用当前工作树，可复用兼容环境。`--offline` 仅省略全局原生预检，不忽略测试失败，也不免除所选测试自身依赖；必须指定文件模式，空匹配会失败。原生／完整验证保留明确 MuJoCo profile、隔离 editable 源码核验和包／原生版本预检。`run_tests.py --check-only --mujoco-profile PROFILE` 只检查运行时。

`check` 和 `submit` 自动识别文字／图片、修改的测试文件及两个工作流入口。其他可执行或机器读取内容必须显式给出 `--test`；未知改动会列出文件后停止，避免猜测覆盖。重复 `--backend` 可选择 apple 双后端，`--full` 执行全量单测及两个完整 14 秒 apple 回合。必要的任务专用命令或历史记录重评分仍须执行并在 PR 记录；apple 门禁不能证明布料、LIBERO、浏览器或其他任务的验收。远端和本地提交沿用同一选择、候选文件树与 base，PR 仅列实际完成的检查。

| 改动 | 合格交付所需验证 |
| --- | --- |
| 文字、链接、架构图 | 相应差异／链接／渲染审查及严格双语构建；不要求单测或物理环境。 |
| 工作流工具、构建／CI、前端 | 相关回归及失败／恢复场景；前端输入变化才跑前端测试，不附加无关 apple 回合。 |
| 离线评分或记录分析 | 语义负例及适用历史记录重评分；只有观测或执行语义变化确实需要时才补原生证据。 |
| 原生模型／控制／求解器／记录器 | 对应任务／后端及独立评分；共享 apple 路径验证双后端，不缩减原任务冻结的验收范围。 |
| 引擎升级或新正式对比 | 独立环境、官方版本／wheel 审计、完整适用任务／引擎资格验证与冻结协议，保留现有基线。 |

所有交付保留 `git diff --check`、严格双语构建、精确文件树审查和适用 CI。聊天任务可直接 Git/GitHub 交付，Issue 提交使用具有相同选择参数的 `submit`；混合改动取相关检查并集。本节替代历史指南中无条件全量单测／双引擎门禁，科学阈值、作者准入、暂停状态与合并保护不变。

### 冻结基线与发行升级

候选原生验证仍需 `DEXLAB_QUALIFICATION_WHEELS`。首次 `apple_admission --preflight` 获取官方稳定元数据，核验实际加载的包／原生载荷与官方 wheel，并在回合开始前保存带日期的运行时记录；预检不等于任务合格。后续原生检查设置 `DEXLAB_RUNTIME_PREFLIGHT=/private/path/to/preflight.json`，即可复用官方审计，同时离线重新核验当前运行时和 wheel 字节。未指定已有记录时，候选原生检查仍做新的发行审计。保留目标环境的 profile 和 wheel 文件，脚本不自动替换环境。

最终双后端准入读取执行前保存的预检，独立重评原始记录并核验源码／运行时未变，不查询最新版本或刷新审计日期。上游新版、跨天或软件仓库离线不能否决冻结基线；运行时、wheel、源码观测变化或物理检查失败仍会拒绝。显式使用 `apple_admission --check-latest` 获取发行新鲜度报告：若出现新版，将已完成证据标记为历史版本，另行安排升级验证，但不否决该批次。正式 benchmark 的新批次入口保留现有新资格验证规则，恢复批次继续沿用原冻结状态。

资源隔离不继承任意环境变量：将 profile、wheel 和已有预检变量放在 `bounded_run.py ... --` 后的实际子命令中。原生资源限制和独立输出尝试规则继续生效。

### 恢复现有 PR 分支

在 `.autoresearch/worktrees/issue-N` 恢复原分支，不为满足标准命名重复开 PR 或重命名原分支。先审查并在本地仅提交本项修改，使恢复工作树保持干净，再在正常资源约束内显式指定关联 PR，运行按范围选择的提交门禁：

```bash
python3 scripts/autoresearch.py submit 177 --existing-pr 180 --summary-file /path/to/review.md
```

恢复会核验 Issue 授权、拉取与推送仓库、PR 归属、`main` base、分支与远端 head 祖先关系。多个 PR 声明同一任务、无关脏文件、外部 remote 或验证中发生身份变化时停止发布。所选门禁和前后文件树检查仍会运行，更新原 PR 后读回实际 head/base。普通标准分支仍在验证后提交已审查的修改。

新建 PR 使用明确仓库与已推送分支的 API，不要求打包安装的 CLI 自动发现本地 Git checkout。发布失败不会抹去已通过的验证，也不能把整条命令改报成功。保留失败记录，重试前先核对远端分支与 PR；仅当已审查 head/tree 和 base 仍匹配已完成检查时恢复未完成的发布步骤。源码或组合树变化后须重新运行适用门禁。此流程不更改主机访问权限、科学阈值或定时状态。[恢复缺口与验收](https://github.com/huangkiki/Dexlab/issues/184)。

## 合并、发布与恢复

维护者 2026-09-29 的授权只允许符合条件的实际 head 合并与 GitHub Release。核对真实 diff、适用 CI、分支保护和未解决意见。自审不是独立批准，没有 CI 不是 CI 通过。组合树变化后重新验证；完全相同的已验收树可按哈希复用对应证据。squash 合并绑定预期 head，不强推 main 或绕过保护。

合并后读回提交／树、构建／部署与线上版本。只有完整自身验收和交付核验满足后才关闭 Issue，不以部分 PR 合并替代。保留剩余工作和真实外部依赖。代码发版在最终验证前更新版本，使用新不可变标签，中英说明及允许分发的小型验证附件，核对公开标签、大小与哈希。每轮最多一个合格代码版本，不发空版、不移动标签、不覆盖旧附件、不隐式发布 PyPI。`apple-stem-assets-v1` 是独立资产标签，不纳入代码版本序列。请求超时先核实远端实际状态；合并成功但发布失败，只恢复发布。[原合并／发版细则](autoresearch-2026-10-10.zh-CN.md)继续生效。

## 交接与解释边界

原子维护简短私有 checkpoint，记录实际句柄、源码／环境、已验收证据与下一步，恢复时重新查真实状态。Obsidian 提交／推送继续暂停。仅汇报交付、重要退化或必需输入，不刷无变化定时状态。克隆仓库不会创建任务或授予合并凭据。不编造真机测量，不承诺无人干预研究一定完成。

未决公开表述、来源或评分歧义进入有界 Issue，包含证据与恢复条件。挂链接、换措辞不是技术关闭。记录可信度、物理结果和因果解释分开。[研究标准](research-focus.zh-CN.md)、[配置角色](solver-taxonomy.zh-CN.md)与[当前工作](current-work.zh-CN.md)约束解释范围；历史评分和阈值不变。
